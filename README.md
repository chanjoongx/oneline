# Oneline

> Software for one. Describe the exact tool you need and get it running on your phone in under a minute. Built for the person asking, not a market.

Oneline turns a one-line description of a tool into a working app on your phone. Each tool is generated by Gemini 3.5 Flash inside a Managed Agents sandbox, judged for quality, deployed, and handed back to you as a QR code. The tools are made for the one person who asked, used, and then thrown away.

## What it is

Most software is built for everyone, which means it fits no one exactly. The tool you need most often is the one nobody built, because the market is just you: a timer for your specific interval, a tracker for the one thing you are watching this week, a calculator for your exact situation.

Oneline lets you speak that need and get a working tool back. You are not a maker shipping to a market; you are the single person the tool is for. When you are done with it, you discard it and ask for the next one.

## How it works

You type a need in plain language. About a minute later you scan a QR code and the finished tool opens on your phone. Inside that minute:

1. A planner reads the request, trims it to the essential scope, and writes three different build strategies.
2. Three candidate tools build in parallel, each in its own Gemini Managed Agents sandbox.
3. A three-layer judge scores every candidate on functionality (Playwright drives the real app inside the sandbox), UX clarity, and design coherence.
4. A selector gates on functionality first, then picks the winner by weighted score.
5. The winner deploys to Cloud Run and a QR code puts it on your phone.
6. Each losing candidate's mistakes are distilled into lessons that make the next build better.

Every model call is `gemini-3.5-flash`. The selector and the default lesson retriever are deterministic, so the parts that have to be predictable are not left to a model.

## The tools it makes

Every tool Oneline produces follows one shared design language, so they feel like they came from the same hand: a dark base, a single accent color, one hero value, a fixed type scale, and an 8px spacing grid. They are mobile-first, built for a phone in portrait, store their data locally in the browser, and have no backend, no accounts, and no sign-in. Open one, use it, close it.

## Project layout

- `core/` orchestration: the planner, the lesson retriever, the selector, and knowledge-base I/O
- `sandbox/` the Gemini Managed Agents client and the three implementers that build candidates
- `judges/` the functionality, UX, and design judges, plus the curator that writes lessons
- `web/` the dashboard, QR generation, Cloud Run deploy, and live status updates
- `shared/` the data contract (JSON schemas), the design tokens (`base.css`), and the knowledge base

A run flows core to sandbox to judges to core (selection) to web (deploy and QR), with the curator feeding new lessons back into `shared/knowledge_base.json` for the next run. The contract every part codes against is documented in `shared/schemas/README.md`.

## Running it

The fastest way to see the whole flow is the dashboard's built-in offline engine, which needs only Node 18+:

```bash
cd web
npm install
npm run dev
# open http://localhost:3000
```

Type a tool you need. By default the dashboard runs a self-contained engine that produces the same three-candidate build, judging, selection, and QR steps as a live run, with the deploy simulated, so it works with no API keys or cloud access.

To drive the real pipeline straight from the dashboard, set `ONELINE_LIVE=1`:

```bash
export GEMINI_API_KEY=your-key          # PowerShell: $env:GEMINI_API_KEY="your-key"
export ONELINE_PROJECT=your-gcp-project  # your Cloud Run project id
export ONELINE_REGION=your-region        # e.g. us-central1

ONELINE_LIVE=1 npm run dev
# open http://localhost:3000
```

Now the dashboard runs the real core pipeline: each candidate builds in its own Gemini Managed Agents sandbox, the three-layer judge scores them, and the winning tool deploys to Cloud Run. This path needs a Gemini API key, `gcloud` authenticated for the deploy, and `ONELINE_PROJECT` and `ONELINE_REGION` set to your own Cloud Run target.

You can also run a single request end to end from the command line with Python 3.12+ and a Gemini API key:

```bash
export GEMINI_API_KEY=your-key        # PowerShell: $env:GEMINI_API_KEY="your-key"

pip install -r core/requirements.txt
pip install -r sandbox/requirements.txt
pip install -r judges/requirements.txt

# one request, end to end: plan, three sandbox builds, judging, selection, deploy, lessons
python -m core.live "interval timer, 90 seconds work 30 rest, 8 rounds"
```

Each module's `README.md` documents its own entry points and tests.

## What it is not

Oneline is not an app builder like Lovable, V0, or Bolt. Those help a maker build an app to ship to other people. Oneline builds a tool for the one person asking, who uses it and throws it away. It is also not a no-code platform: real code is generated, the user just never has to see it.
